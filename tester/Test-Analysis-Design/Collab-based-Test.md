# Acceptance Criteria
- Define the scope of a user story
- The outcome of stakeholder consensus 
- Can include positive and negative scenarios
- Can include non-functional requirements

![App Screenshot](/images/Acceptance-Criteria.png)

# Acceptance Test-driven Development
-  Aims to prevent defects rather than indentifying them in the implementation
- Test cases are created before a user story is implemented
- Test execution may be manual or automated

# The ATDD Process
- Draft user story
- Workshop
- User story
- Test cases created
- User story implemented
- Software with less defects

# Test Cases
- Must be understandable by all stakeholders
- The scope must exactly match that of the user story
- Each test case should cover a unique aspect of the user story

# Deriving Test Cases with ATDD
- As an unauthenticated user, I want to create an account, so that I can access the application 
### Requirements
- Email address must not already be associated with an account
- Password must between 8-50 characters
- Submitting invalid credentials should result in a validation error message being displayed
- Submitting valid credentials should result in an account being created and the usesr being redirected to their profile page
